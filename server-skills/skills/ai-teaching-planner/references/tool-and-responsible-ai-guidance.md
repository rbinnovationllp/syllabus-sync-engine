# Tool guidance and responsible-AI teaching rules

## Describing any AI tool used in a lesson

Never just name a tool — always cover:

- Tool name and educational purpose
- What the tool can do; its important features
- How each *relevant* feature works (relevant to this lesson, not an exhaustive feature dump)
- Age group it's suitable for, and minimum-age/account requirements
- Free, freemium, or paid — and what that tier actually includes
- Device and internet requirements
- Step-by-step classroom use
- An example student task using it
- Privacy and safety considerations
- Limitations and likely errors
- Teacher-supervision requirements
- A free/low-cost alternative
- A no-device/offline alternative, where one exists

**Currency rule**: do not state a tool's price, minimum age, feature set, or privacy policy as current fact unless you've verified it (web search when these specifics matter for the lesson). If you can't verify, say plainly what the teacher needs to confirm before using it in class — don't guess and present it as settled.

## Responsible and safe AI — core ideas to weave in (calibrate by ELI level per the class-band reference file)

- AI can make mistakes.
- AI-generated information must be verified.
- Don't share personal information carelessly.
- AI can reflect bias present in its training data.
- AI-generated images/audio/video can be misleading (deepfakes).
- Don't use AI for cheating or plagiarism.
- AI should not replace independent thinking.
- Human supervision and judgment remain necessary.
- Respect copyright and give attribution.
- Disclose AI assistance where required.
- Follow school rules and tool age restrictions.

**Younger bands (Classes 1–5)**: teach these through simple rules, short stories, and concrete examples — not abstract principles.
**Older bands (Classes 6–12)**: use case studies, fact-checking exercises, debates, and (from Classes 9–12) structured ethical-analysis frameworks and project documentation requirements.

## Projects — safety and scope rules

- Address a real school/home/accessibility/environment/agriculture/health/community problem.
- Age-safe and age-appropriate in scope.
- State required materials/tools plainly; give step-by-step instructions and a defined expected outcome.
- Specify how students document work (project-report format).
- Include presentation/viva questions and an assessment rubric.
- Require students to explain their own reasoning (not just present output).
- Avoid unnecessary collection of personal/sensitive information.
- Don't make the project entirely dependent on a paid tool — give a low-tech/offline alternative wherever feasible.
