# Output template

Use this structure for every lesson/module. Skip a section only if it's genuinely inapplicable (e.g., section H if no tool is used) — say so briefly rather than silently dropping it. Full-course requests additionally need section S.

## A. Module information
Course name · Class · Approximate age · ELI level · Topic · Subtopics · Lesson number · Duration · Language · Prerequisite knowledge · Connection to previous lesson · Recommended next lesson.

## B. Learning outcomes
Clear, measurable objectives: students should be able to *understand / explain / identify / compare / demonstrate / create / apply / evaluate* — pick the verbs that actually fit this lesson's depth (don't claim "evaluate" for an ELI6 lesson).

## C. Key vocabulary
Term · simple meaning · age-appropriate definition · Hindi/requested-language equivalent (if applicable) · example sentence or situation, for each important term introduced.

## D. Complete topic explanation
Detailed explanation · step-by-step breakdown · age-appropriate examples · Indian/local-context examples · a helpful analogy or story · distinctions between related concepts (AI vs. software vs. automation vs. robots, etc., as relevant) · how the technology works · what it can/cannot do · limitations and risks · common misconceptions · responsible/safe use. This must be detailed enough for the teacher to teach it with no further research.

## E. Teacher's teaching script
Suggested language for: opening the class, introducing the topic, explaining each concept, questions to ask students, running the demonstration, managing the activity, discussing ethics/safety, summarising, and bridging to the next topic. Write this in the register a real teacher would use for this age group.

## F. Period-wise lesson plan
Table:

| Time | Teaching stage | Teacher action | Student action | Resources | Expected outcome |
|---|---|---|---|---|---|

Stages follow the Connect→Introduce→Explain→Demonstrate→Explore→Apply→Reflect→Assess→Continue sequence. Make sure the total time adds up to the stated class duration — this is a common failure point, check the arithmetic.

## G. Examples and demonstrations
At least two everyday examples · one school-related example · one Indian/community-related example · one practical demonstration · expected observations · discussion questions.

## H. Tool guidance (when a tool is used)
See `tool-and-responsible-ai-guidance.md` for the full required fields and rules.

## I. Classroom activity
Title · objective · materials required · group size · teacher preparation · step-by-step procedure · student instructions · expected result · discussion questions · safety/privacy precautions · differentiation for different learning levels.

## J. Practical / coding / no-code task (where appropriate)
Platform or language · setup instructions · step-by-step task · explained code (if coding) · expected output · common errors and troubleshooting · extension challenge · no-code/offline alternative.

## K. Questions students may ask
Likely questions with clear, age-appropriate answers.

## L. Misconceptions and teacher alerts
Common misunderstandings · incorrect examples students might latch onto · how to correct them · sensitive/unsafe/misleading claims to actively avoid repeating.

## M. Understanding check
Oral questions · quick classroom check · short written exercise · observation points · expected answers.

## N. Assessment
Age-appropriate mix from: MCQ, true/false, fill-in-the-blank, short-answer, scenario-based, practical task, reflection question, viva questions. **Always** provide a separate answer key and marking rubric. Questions must map to what was actually taught in this module.

## O. Homework or extension activity
Clear instructions · expected submission · estimated completion time · parent involvement (only if genuinely appropriate) · safety/privacy guidance · offline alternative.

## P. Accessibility and differentiation
How to adapt for: students needing extra support, advanced students, students without devices, students without internet, students with disabilities, students learning in another language.

## Q. Teacher preparation and resources
Materials required · software/accounts required · preparation checklist · printable resources · visual-aid suggestions · classroom setup · technology backup plan · low-resource alternative.

## R. Lesson conclusion
Student-friendly summary · key takeaways · exit-ticket question · teacher reflection points · recommended next module.

---

## S. Full-course output (for weekly/monthly/term/year requests)
Course purpose · class-wise curriculum · unit-wise syllabus · academic-year structure · weekly/period-wise schedule · learning outcomes per unit · detailed lesson sequence · tools used per unit · practical activities · projects · revision lessons · assessments · examination plan · answer keys · rubrics · teacher handbook · student resources · required infrastructure · progress-tracking method · final project/exhibition · responsible-AI integration woven throughout (not a single bolted-on unit).

For a full-year or term curriculum, don't write out every single lesson at full A–R depth in one response — provide the full syllabus/sequence structure (S), then offer to generate any individual lesson at full A–R depth on request. Doing otherwise produces an unusably long single output.

## T. Syllabus Synk annual plan (Mode 2 — new annual plan)
See `syllabus-synk-integration.md` for the full method. The output itself should contain:

**Header**: Class · academic year/session dates · board/curriculum (if any) · periods/week · period duration · facilities assumed · prior-knowledge starting point · language.

**Capacity arithmetic (shown, not just stated)**: total session weeks → deducted weeks (with reasons: vacations, exams, events) → net teaching weeks → total AI periods available.

**Period-type distribution**: a table of how the total periods split across theory / practical / assessment / project / revision / buffer, with the percentages/counts used and a one-line rationale.

**Week-by-week / period-by-period grid**:

| Week | Period | Topic | Subtopic | Period type | Learning outcome | Resources needed | Linked assessment/project |
|---|---|---|---|---|---|---|---|

Sequenced from the relevant band's topic list in `classes-*.md`, foundational → advanced, with responsible-AI content woven into relevant topic weeks rather than isolated into one unit.

**Milestones**: unit boundaries, project checkpoints, assessment windows, and where buffer/remedial capacity sits.

As with section S, don't expand every period to full A–R depth in this output — deliver the grid plus milestones, and generate any individual period's full lesson (structure U) on request.

## U. Today's lesson from a plan (Mode 1, or Mode 2 follow-up)
**Plan-lookup summary** (short, at the top): class · week · period · date if known · topic identified from the plan · period type · status (on-track / rescheduled / makeup class), with the reason if not on-track.

Then the **full A–R lesson** for that topic, exactly as in a standalone lesson request, calibrated to the class's band and ELI level as usual.

Close with an **updated tracker note**: mark this period as delivered once produced, and preview the next 1–2 scheduled periods so the teacher can see what's coming. If holidays/events have consumed periods since the plan was last checked, show the revised remaining schedule per the rescheduling rules in `syllabus-synk-integration.md` and ask the teacher to confirm it before continuing.
