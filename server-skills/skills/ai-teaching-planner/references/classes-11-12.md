## Calibration for this band
- **Language**: full technical register — students should be able to read introductory ML material and industry explainers after this band, still with terms defined on first substantive use in a lesson.
- **Depth**: mechanism-level understanding — *how* logistic regression separates classes, *why* overfitting happens, *what* an embedding actually represents — not just definitions.
- **Examples**: real-world systems (recommendation engines, fraud detection, medical imaging aids, translation tools), Indian industry and public-sector AI applications, and student-relevant contexts (career paths, entrepreneurship).
- **Lesson length**: 40–60 min for concept lessons; double periods or multi-day blocks for project/lab work.
- **Activities**: implementing small models in Python (e.g., scikit-learn), visualizing decision boundaries, evaluating a model with a full confusion matrix and metrics, working with an LLM API for a bounded task, structured debates on AI's social/economic effects.
- **Math**: real but school-appropriate — algebra-level regression math, basic probability/statistics, intuitive (not full derivation) explanation of gradient descent, vectors/embeddings explained geometrically rather than via full linear algebra unless the student's stream already covers it.
- **Coding**: Python-based projects are the default; use accessible libraries (scikit-learn, pandas) and, for LLM topics, simple API calls — always with a no-code/low-resource fallback (pre-built notebooks, hosted no-code ML tools) for schools without lab access.
- **Projects**: substantial multi-week capstone projects tackling a genuine community problem (health, agriculture, accessibility, environment, local governance/business), including a project report, viva, and rubric-based assessment.
- **Assessment**: exam-style question banks with MCQ, numerical/short-answer, scenario and case-study questions, applied coding tasks, and project-based assessment with a detailed rubric; explicitly test explainability/limitations reasoning, not just implementation.
- **Responsible AI**: structured frameworks for fairness/accountability analysis, explainability techniques at a conceptual level, privacy/cybersecurity practices for real projects, and discussion of AI's societal and economic impact including career implications.

## Sample framings that work at this level
- Overfitting: a student who memorizes past exam papers verbatim scores perfectly on those papers but poorly on a new one — the model needs to learn the underlying pattern, not the specific examples.
- Embeddings: representing meaning as coordinates in space, where similar meanings end up near each other — like plotting cities so that culturally similar ones cluster, even if geographically far apart.
- Transformers/attention (conceptual only): the model learns which other words in a sentence matter most for understanding each word, rather than reading strictly left to right.

Avoid presenting this band's math/code as if for a university ML course by default — ground every mechanism in an intuitive explanation and a runnable, school-lab-feasible example unless the user asks for the advanced extension.
