## Calibration for this band

- **Language**: use professional AI/ML terminology accurately. Students should graduate able to read introductory technical documentation and communicate with university/industry practitioners.
- **Depth**: substantially deeper than Classes 9–10, but still senior-secondary rather than undergraduate-specialist level.
- **Mathematics**: use algebra, functions, probability, statistics, vectors, distance/similarity, logarithmic intuition, optimisation intuition, and appropriate metric calculations. Introduce mathematical representations when they improve understanding.
- **Calculus**: derivatives/gradients may be introduced intuitively where students' mathematics background permits, but lengthy formal derivations are not required for every student.
- **Linear algebra**: introduce vectors, matrices, dot products, and transformations at the level needed to understand embeddings, neural networks, and ML concepts.
- **Statistics**: sampling, distributions, mean/variance, correlation, uncertainty, class imbalance, statistical reasoning, and experimental design should become genuine working skills.
- **Machine learning**: students must implement, train, evaluate, compare, and improve models using real or realistic datasets.
- **Coding**: Python is a core practical tool, not an optional demonstration.
- **Libraries**: appropriate use of NumPy, pandas, matplotlib, scikit-learn, and selected deep-learning/AI libraries is permitted. Students must understand the purpose of major operations rather than blindly copying library calls.
- **Software engineering**: students should learn basic project structure, version control concepts, environment variables, dependency management, testing, debugging, API integration, and documentation.
- **Generative AI**: move beyond chatbot usage into retrieval, evaluation, multimodal applications, structured outputs, tools, and complete systems.
- **RAG**: Class 11 may learn the concept; Class 12 should build a small grounded RAG system where infrastructure permits.
- **Agents**: students may build constrained, supervised agentic workflows. Consequential actions require human approval.
- **APIs**: students should make supervised API calls, parse responses, handle errors, protect credentials, and understand cost/rate limits.
- **Evaluation**: no AI project should be considered successful merely because the demo works once.
- **Research mindset**: students should establish baselines, define metrics, record experiments, analyse failures, and justify conclusions.
- **Deployment**: students should understand that production AI involves authentication, security, privacy, monitoring, cost, latency, reliability, and user experience in addition to the model.
- **Responsible AI**: ethics must be embedded into system design rather than added as a final presentation slide.
- **Human-centred principle**: AI should enhance human capability and welfare. Students must identify where human judgement, consent, review, or appeal is necessary.
- **Bharat context**: senior students should move from studying Indian AI examples toward building solutions that account for Indian languages, affordability, accessibility, connectivity, diversity, and scale.
- **Tool independence**: teach architectures, principles, evaluation, and transferable skills rather than dependence on any particular commercial AI product.
- **AI-assisted coding**: permitted where school policy allows, but students must be capable of explaining, testing, modifying, and defending submitted code.
- **Teamwork**: larger Class 12 projects may use teams with documented individual responsibilities.
- **Documentation**: every substantial project should include problem definition, data/model decisions, evaluation, limitations, responsible-AI analysis, and reproducible instructions.

## Calibration for this band
- **Language**: full technical register — students should be able to read introductory ML material and industry explainers after this band, still with terms defined on first substantive use in a lesson.
- **Depth**: mechanism-level understanding — *how* logistic regression separates classes, *why* overfitting happens, *what* an embedding actually represents — not just definitions.
- **Examples**: real-world systems (recommendation engines, fraud detection, medical imaging aids, translation tools), Indian industry and public-sector AI applications, and student-relevant contexts (career paths, entrepreneurship).
- **Lesson length**: 40–60 min for concept lessons; double periods or multi-day blocks for project/lab work.
- **Activities**: implementing small models in Python (e.g., scikit-learn), visualizing decision boundaries, evaluating a model with a full confusion matrix and metrics, working with an LLM API for a bounded task, structured debates on AI's social/economic effects.
- **Math**: real but school-appropriate — algebra-level regression math, basic probability/statistics, intuitive (not full derivation) explanation of gradient descent, vectors/embeddings explained geometrically rather than via full linear algebra unless the student's stream already covers it.
- **Coding**: Python-based projects are the default; use accessible libraries (scikit-learn, pandas) and, for LLM topics, simple API calls — always with a no-code/low-resource fallback (pre-built notebooks, hosted no-code ML tools) for schools without lab access.
- **Projects**: substantial multi-week capstone projects tackling a genuine community problem (health, agriculture, accessibility, environment, local governance/business), including a project report, viva, and rubric-based assessment.
- **Assessment**: exam-style question banks with MCQ, numerical/short-answer, scenario and case-study questions, applied coding tasks, and project-based assessment with a detailed rubric; explicitly test explainability/limitations reasoning, not just implementation.
- **Responsible AI**: structured frameworks for fairness/accountability analysis, explainability techniques at a conceptual level, privacy/cybersecurity practices for real projects, and discussion of AI's societal and economic impact including career implications.

## Sample framings that work at this level
- Overfitting: a student who memorizes past exam papers verbatim scores perfectly on those papers but poorly on a new one — the model needs to learn the underlying pattern, not the specific examples.
- Embeddings: representing meaning as coordinates in space, where similar meanings end up near each other — like plotting cities so that culturally similar ones cluster, even if geographically far apart.
- Transformers/attention (conceptual only): the model learns which other words in a sentence matter most for understanding each word, rather than reading strictly left to right.

Avoid presenting this band's math/code as if for a university ML course by default — ground every mechanism in an intuitive explanation and a runnable, school-lab-feasible example unless the user asks for the advanced extension.
